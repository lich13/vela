# 账号与客户端配置

## DeepSeek Harness

主窗口的 DeepSeek Harness 视图与 Codex、Claude Code、Grok Build 使用同一个本地监听，但拥有独立供应商、健康状态、调度、凭据和模型目录。接入入口只显示 DSH profile 的脱敏信息；旧版仅有 `config.yaml` 时提示升级，不自动迁移。

每个 profile 选择一种路由协议。`openai-completions` 和 `openai-responses` 使用 `/v1`，`anthropic-messages` 使用根基址。模型列表来自支持所选协议的在队供应商并集及手动项；列表为空时可手填明确模型 ID。统一接入管理 `agent-default-model`，只影响新会话。

接入会保留 DSH YAML 注释、未知字段、其他 provider 和外部配置修改。供应商 Token 留在本应用 Rust 凭据存储；DSH 文件只引用本地网关 token。停止和恢复仅处理受管行，不整文件回滚；遇到外部修改会保留现场。

“统一接入”默认从 desktop 当前连接预填供应商、协议和模型，将可用凭据导入供应商库，再同步全部已有 profile。写入前预检全部目标，按 profile 串行提交，不自动创建 profile。每项显示完成、失败或未执行；失败保留此前成功项，并在进程内还原失败项，外部修改保持原样。所有受管 profile 共用首次接入前的凭据快照；已有 home patch 和旧版 settings 覆盖同步写入；全局停用逐项恢复配置，最后解除时恢复共享凭据和全局覆盖。切换协议需先停用。

接入支持空数组及多行 patch，并保留注释和未知条目。非空的行内数组需先在配置编辑器展开为多行 YAML 数组；无法安全编辑时保留原文件并提示处理。

配置页选择 DSH 后，默认打开实际存在的 desktop patch，切换 profile 自动显示其文件。可编辑 profile patch、home patch 和已存在的旧版 `settings.yaml`，无需 bundle 解析成功。`.env` 和 `.credentials.yaml` 只显示名称与遮蔽值。保存和恢复都校验原文件版本与待写入内容，接入期间保护路由和受管默认模型，包括全局覆盖入口。每文件保留一份上一版私有原文备份；失败保留草稿，切换文件前确认未保存修改。

当前供应商依据可确定的 profile、bundle、profile patch、home patch 和旧版 settings 读取，不以“已接入”代替实际选择。home 覆盖单独提示；启动参数、其他进程环境和项目覆盖无法确认时降低判断置信度。凭据优先读取已存文件，再参考当前可见环境和 home `.env`，不执行 shell 或动态 YAML。bundle 查找支持 DSH home 下的 `runtime/node_modules`、`lib/node_modules` 及 PATH 中实际可执行文件的祖先目录；bundle 只补充默认配置；桌面安装缺少 npm bundle 时，完整的用户 patch 仍可识别、编辑和接入。

存在多个 profile 时，仅在其静态供应商与模型选择一致时展示共同结果；选择不同时显示“配置不一致”，网关页和接入面板逐项显示实际选择。最后同步的 profile 不代表原生启动器的实际选择，参见 [DSH 启动参数](https://github.com/deepseek-ai/deepseek-harness/blob/master/apps/cli/src/args.ts)。

## Claude 模型发现

Claude 网关只自动管理地址和令牌两个字段。模型发现由用户手动开启 `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1`；客户端会过滤、排序和合并网关返回的模型选项，因此界面不保证逐一展示网关返回的全部 ID。

## Grok Build 配置来源

Grok 导入预览按系统 managed、用户 managed、用户配置、用户 requirements、系统 requirements 的顺序读取。预览会标出模型、地址、协议、凭据可用性、缺失环境变量和无法由 GUI 确认的 `GROK_HOME`、CLI 临时模型、`/model` 选择及远端 campaign 状态。写入只修改用户文件中已确认的受管字段；requirements 或明确环境覆盖阻止接管时显示具体原因。状态读取与接管限制分开：默认模型按 requirements 固定约束、环境变量、用户配置、managed 默认值确定，残留受管模型表不会改变有效选择；模型自己的凭据优先于全局官方登录偏好。状态和预览共用全局地址、模型覆盖和 endpoint.env 的简单赋值解析，凭据不进入前端状态；未入库连接显示“已识别、未导入”。地址唯一且凭据不可得时显示“按地址匹配”，已知凭据不同不降级匹配。

## Codex 账号

启动及每 2 秒检查当前 `auth.json`，文件身份和时间等元数据未变时复用内存结果，变化或元数据不可靠时稳定读取：已有身份的更新版本同步入库，新身份自动加入列表。ChatGPT 优先按一致的 `chatgpt_user_id`／`user_id` 与工作区区分，缺失稳定用户 ID 时回退到 `sub` 与工作区；API Key 按指纹区分。邮箱与套餐不参与唯一身份判断，矛盾的身份字段拒绝覆盖。优先比较有效 Token 签发时间，没有可比较时间时再使用有效 `last_refresh`（兼容秒、毫秒和 RFC3339），保留已保存的较新凭据并提供“使用已保存版本”；单个账号的日常同步在无法可靠排序时采用最近检测到的稳定内容。监控不回写 auth 或配置，无效／缺失文件不会删除账号。删除账号后，同一文件版本在重启后也不会重新入库，出现新版本才重新收录。

读取旧账号库时，确认属于同一用户及工作区的重复项会合并，保留最早条目的 ID、名称和位置，采用可确认较新的凭据，不按套餐高低选择。兼容的未知字段和账号交换元数据保留；身份或扩展字段冲突、两份不同凭据无法判断新旧时保留原记录并报错。规范化提交检查文件版本，不覆盖外部修改，也不改写当前 `auth.json`；失败可在问题排除后重试。套餐取自实际凭据，刷新不会额外联网推断订阅。

点击“添加账号”通过官方 Codex CLI 登录；账号页“导入”支持完整 Codex `auth.json`、Sub2API `openai/oauth` 和 CLIProxyAPI `type=codex` JSON。预览后可部分选择，重复账号默认跳过，明确勾选后更新；导入仅保存账号，不自动激活。

账号页“导出”提供 Sub2API 多账号单文件和 CLIProxyAPI 每账号一个 JSON。OAuth 使用独立模板，保留识别出的行为配置；真实 Token、身份和有效期取自所选账号，不生成替代 `id_token`。同一账号原格式往返保留专用元数据，外部格式的附加信息不写入客户端认证文件。其他平台、不兼容认证模式及缺失凭据会明确提示。

选择账号后仅替换认证文件，配置保持不变。现有 Codex 进程可能缓存凭据，需要自行重新打开。

ChatGPT 登录需要本机已安装 [官方 Codex CLI](https://developers.openai.com/codex/cli)。应用自动查找 PATH、常见安装目录和 macOS nvm；旧安装中的 CLI 路径偏好继续兼容。Windows npm 安装使用同目录 Codex JavaScript 入口和 Node.js。登录使用独立临时目录；成功后若与当前账号相同，更新账号库和当前 `auth.json`，其他账号仅加入列表；10 分钟未完成会取消。浏览器授权需本人完成，也支持设备码登录。浏览器回调无法到达本机 CLI 时（例如浏览器在另一台设备上），请改用设备码登录。

账号页的 ChatGPT 账号可启用“官方账号”。启用会先正常停用 Codex 网关，再注释现有 custom 的 `base_url`、`experimental_bearer_token` 和 `supports_websockets` 三个独立字段，并切换该账号；关闭时按事务记录精确恢复原行文本。官方连接期间不能启动 Codex 网关或编辑这三个字段，其他配置仍可编辑；外部修改受管行会显示冲突。关闭后不会自动启动网关。

默认目录为 `CODEX_HOME` 或 `~/.codex`（Windows 为用户主目录中的 `.codex`），旧路径偏好继续兼容。账号切换仅影响文件；`keyring` / `auto` / `ephemeral`、provider bearer token、环境变量或命令认证可能使用其他来源。

配置页按原文保存，保留注释、未知字段和换行。外部修改发生时保留未保存草稿并阻止覆盖；复制草稿、重新读取并合并后保存。删除列表中的账号不会注销当前 Codex。

每个 ChatGPT 账号行提供“设备码刷新”，用于更新指定账号的凭据。完成同一用户的官方 CLI 隔离登录后，整组替换 Token 及配套账号字段，工作区变化不再拦截，也无需额外选择工作区。保留账号名称、顺序和扩展字段；登录到其他用户时拒绝覆盖。当前磁盘账号同步更新 `auth.json`，其他账号仅更新账号库。登录期间账号或磁盘凭据变化时停止覆盖；刚完成的有效官方登录不会因旧刷新时间被拒绝。

## Antigravity 账号

“账号 → Antigravity”只在已保存的 OAuth 账号之间切换，没有导入、添加或认证方式的入口；账号全部由 Vela 自动识别。列表显示名称和邮箱，支持切换、重命名和删除；正在使用的账号标记“当前生效”，需先切换到其他账号才能删除。还没有账号时显示“尚无已保存的 Antigravity 账号”及“在 Antigravity app 内登录后，Vela 会自动识别并加入切换列表。”

在 App 内登录新的 OAuth 账号后，Vela 会在几秒内识别并加入切换列表，同时提示“新账号已自动加入切换列表”；不需要打开配置页或保持主窗口可见。macOS 上只使用当前 App 的登录钥匙串项目，通过系统 `/usr/bin/security` 访问（切换账号写回时经 `security -i` 标准输入传入凭据且不经命令行参数，写回命令上限 4096 字节），并按 `~/Library/Keychains/login.keychain-db` 文件元数据指纹缓存成功结果，避免重复调用子进程或每次升级重弹授权框；项目不存在、为空或无法解码时显示未登录，旧令牌文件不再参与识别。读取失败保留已有账号状态，同一错误只记一条同步日志，后续轮询及手动刷新可重试。Windows 上 App 把登录保存在“凭据管理器”（目标名 `gemini:antigravity`），Vela 通过系统凭据接口先读它，没有该项目时再读令牌文件 `~/.gemini/jetski-standalone-oauth-token`；切换账号写回凭据管理器（令牌文件已存在时一并更新），登录超过 2560 字节时改写令牌文件并移除凭据管理器中的旧项目，删除账号时两处的残留登录都会移除。

新账号提示在任意主窗口页面显示；主窗口隐藏时保留提示，重新打开后显示一次，手动刷新发现的新账号同样提示。已有账号令牌刷新不触发新增提示。账号同步日志保留具体错误码与原因；钥匙串锁定或未授权时，可在 Antigravity 账号页刷新并完成系统授权。

切换只写回所选账号的 OAuth 登录，不改动 App 的其他设置。macOS 上 App 正在运行时先让它退出，写回后自动重新打开，并提示“已切换到 … 并自动重启 Antigravity”；等待退出超时则不做任何修改，自动打开失败时切换仍然生效并提示手动打开应用。Windows 只写回令牌文件，不退出或重启 App。切换前核对账号状态，已变化时提示刷新后重试；写入失败恢复原来的登录和账号库。用量仍从 App 采集，并按切换时间归属到当时生效的账号。

Antigravity 新登录最初不带邮箱，首次刷新令牌后才补上；Vela 按同一个刷新令牌认作同一账号，补上邮箱后沿用原条目并改用邮箱作名称（已手动改过的名称保留），旧版本因此留下的“OAuth 账号”占位项会自动并回对应账号。`agy` 与 Antigravity app 共用同一份登录：每个运行中的 `agy` 会话沿用启动时的账号，并在刷新令牌时（约每小时）把它写回，表现为切换或重新登录后又变回原账号。账号页检测到运行中的 `agy` 会话时会显示提示，切换成功的通知也会提醒；请先退出这些会话再切换，或切换后重新打开它们。Vela 不会结束 `agy` 会话。

Vela 不为 Antigravity app 提供网关或转发，App 的请求由 App 自行直连，不受冻结和网关设置影响。账号页也不读取、不修改 App `config.json` 的 `userSettings.enableAdc`：该项为 `true` 时 App 使用 Google Cloud ADC 而不是 OAuth 登录，切换账号不改变 App 实际使用的身份，需自行改为 `false`（可在“配置 → Antigravity app”的“高级”分组或 JSON 模式修改）。

## 配置页的可视化

配置页的客户端切换依次为 Codex、Claude Code、Antigravity、Grok Build、DeepSeek Harness，每个视图都能切到其余四个。所有平台的配置文件都有“可视化”与原文两种模式，共用同一份内存草稿；切换模式不保存，保存、校验、恢复上次配置与各平台原有的保护（网关接管中的受管字段、外部修改冲突等）不变。

- **Codex 与 Grok 的 `config.toml`、DSH 的 YAML 文件**：“可视化｜原文”。可视化先列出该平台的常用设置分组（文件里还没有的键也能直接设置），最后的“全部设置”按实际类型列出文件里的所有键：第二层分栏为“顶层字段”和每个顶层表或数组各一栏，嵌套的表直接显示，不需要展开。DSH 的 patch 文件没有固定键，只有“全部设置”；`.env` 与凭据文件维持只读。
- **Codex 的具名子表**：另有“模型供应商”（`[model_providers.<名称>]`）、“配置档”（`[profiles.<名称>]`）和“MCP 服务器”（`[mcp_servers.<名称>]`）三个分页，分页内以第二层分栏列出各子表，选中的子表直接显示该类子表的常用字段和它的其余字段。分页底部可填名称和首个字段新增子表（新增后自动选中），子表内的“添加字段”可加入未列出的键（文本、数字或开关）。凭据类的键只读，新增凭据类字段同样需到原文模式。
- **Antigravity**：文件选择“App 配置｜CLI 配置”，分别是 App 的 `config.json` 与 Antigravity CLI 的 `~/.gemini/antigravity-cli/settings.json`，都有“可视化｜JSON”。CLI 表单分为外观与交互、执行与安全（含权限规则）、模型、状态栏与标题、高级；CLI 不从该文件读取的 `enableTelemetry` 与 `hooks` 不提供。CLI 配置文件不存在时显示“尚未找到 Antigravity CLI 配置文件，首次运行 agy 后生成”，Vela 不会创建它。切换文件前会确认未保存的修改。
- **开关**：布尔值一律显示为开关；Claude 的“模型”“偏好”分组列出常用环境开关（使用 Amazon Bedrock／Google Vertex AI，停用遥测、错误上报、自动更新、非必要网络请求、非必要模型调用、费用提醒和终端标题更新），未设置时为关，打开写入 `"1"`；未列出的环境变量值为 `0`／`1`／`true`／`false` 时也自动显示为开关；值恰为 `0`／`1`、`"0"`／`"1"` 或 `"true"`／`"false"` 的标志也显示为开关，写回时保持原来的写法，旁边可改回输入框；名称表示数量的键（超时、次数、大小等）仍按数字编辑。“默认”表示未设置，恢复默认只删除该键。
- **保留原文**：TOML／YAML 的每次修改只改动对应的一处，注释、未知键、顺序、缩进和换行（含 CRLF）不变。日期、空值、多行文本、数组里的表以及 YAML 标签和别名显示“在原文中编辑”。
- **凭据**：名称像凭据的键（token、secret、password、authorization、api key 等）在 TOML／YAML 的可视化里只显示“已设置”，不显示也不能修改，需到原文模式编辑。
- 浏览器预览不解析 TOML／YAML，这三类文件在预览里停留在原文模式。

## Claude 可视化配置

配置页选择 Claude Code，仅编辑当前 `CLAUDE_CONFIG_DIR` 或 `~/.claude` 中的全局 `settings.json`。默认以模型、权限、偏好、环境变量和高级分组编辑；“高级”以第二层分栏列出“顶层字段”和每个顶层对象或数组，嵌套内容直接显示（Antigravity 的 App 与 CLI 配置相同）；JSON 模式提供原文、高亮、查找、折叠及显式格式化。两种方式共用内存草稿，切换不会自动保存。项目、组织配置和 `~/.claude.json` 不在编辑范围。

默认模型支持供应商列表与完整 ID 手填；已有 `ANTHROPIC_MODEL` 优先于根节点模型，推理强度写入支持 `max` 的 `CLAUDE_CODE_EFFORT_LEVEL`。权限规则可通过工具、匹配内容、处理方式添加或原文修改，不自动放宽权限。未知字段通过高级树增删，已有插件、Hook 和状态栏配置完整保留；编辑不会安装插件或执行 Hook。

“默认”表示未设置；零、关闭和空字符串分别保留。恢复默认只删除选定字段。查看改动会遮蔽敏感值，“恢复上次配置”先载入草稿，再由用户保存。`Cmd/Ctrl+S` 保存前校验 JSON、重复键和已知类型；其他字段、格式及 CRLF 保留。外部修改造成版本冲突时保留草稿。

网关运行或有待恢复事务时，编辑器不能改变其两项连接字段，其他设置可以保存；网关关闭时可显式修改，但不会自动新增或切换供应商。模型、环境等设置保存后提示重新打开 Claude Code；普通偏好显示保存结果。其他终端、项目及组织配置仍可能覆盖当前文件。参见 [Claude 配置](https://code.claude.com/docs/en/settings) 与 [模型优先级](https://code.claude.com/docs/en/model-config)。

## Claude 官方／API 配置

Claude 网关页和配置页提供“官方／API”切换。首次启用官方配置前，先退出正在运行的 Claude Code 会话；应用正常停止 Claude 网关，保存当前 API 档，再写入最小官方配置。后续可在配置页保存自己的官方偏好。返回 API 恢复原连接配置，但不会自动开启网关。普通供应商切换仍只管理地址与认证两个字段。

全局文件按角色处理：

| 文件 | 切换行为 |
| --- | --- |
| 当前配置目录中的 `settings.json` | API 档保存原文；官方档首次不继承 API 连接、模型映射及 Hook／插件设置，之后保留官方偏好 |
| 当前配置目录中的旧 `claude.json` | 记录存在状态并暂存，防止成为旧 API 回退入口；返回 API 时恢复 |
| 当前配置目录中的 `config.json` | 只移除并恢复原有 `primaryApiKey`，不改变其他字段，不凭空创建文件或 Key |
| 对应的全局 `.claude.json` | 只处理 API Key 批准记录及首次未登录初始化；保留有效官方账户、机器身份、MCP 与项目信任 |
| `.credentials.json`、macOS Keychain | 不替换、不复制、不删除、不回滚，由官方 CLI 管理 |

默认目录使用用户主目录的 `.claude.json`；指定配置目录时使用该目录中对应的 `.claude.json`。切换校验文件版本、严格 JSON 和重复键；遇到外部受管字段修改会停止并保留现场。辅助文件缺失不会为清理而创建。部分写入失败由恢复事务处理，只恢复仍能确认属于本次操作的内容；CLI 新写入的账户和初始化状态不会随返回 API 而整份回滚。

“官方登录”调用本机 `claude auth login --claudeai`，授权完成后读取 CLI 实际登录状态。应用不修改 `claude` 命令、PATH、shell、项目设置、Skills 或 MCP，不强制终止会话。项目、IDE、环境变量或组织策略仍可能覆盖全局配置；可识别的覆盖会显示提示。官方配置用于避免连接混用，不保证所有启动入口完全隔离，也不承诺避免账号封禁。

## CC Switch 链接

收到 CC Switch 链接后直接进入本应用的供应商导入确认，显示客户端、名称、地址和遮蔽凭据。确认只新增供应商，不切换当前连接、不启停网关。已有表单和草稿会保留，导入排队处理；重复投递不会重复导入。

安装版每次启动核对系统关联并设为本应用。系统要求确认时使用原生流程；未完成或失败会明确提示。开发与测试实例不更改真实系统关联。设置不再提供接收应用选择，旧接收偏好与本应用创建的外部处理器注册会清理。

支持 `ccswitch://v1/import?resource=provider&app=codex` 和 `app=claude`。重复检测按客户端隔离，部署子路径原样保留，凭据只在 Rust 内存中等待确认。其他资源、客户端、脚本和远程配置显示不支持，不转交外部应用。

## 供应商测试与检测

各网关的供应商行提供“连接测试”按钮；快捷面板也有同款入口，点击打开主窗口对应客户端与供应商的测试弹窗，不自动发送请求。弹窗固定当前供应商，四客户端的普通供应商均可切换模型指纹和定时检测；结果和停止操作只作用于当前供应商。连接测试统一普通对话，可编辑测试文案；Claude 使用 Messages，DSH 保留原生协议和模型映射。

测试文案由四客户端及所有供应商全局共用，停笔 500ms 自动保存；关闭弹窗、切换客户端、主窗口导航、快捷入口跳转和开始测试前等待最新输入保存完成。保存失败保留草稿并可重试，离开时需明确放弃；空白不覆盖旧文案且不能发送。运行事件不覆盖输入，已创建任务使用启动时的文案快照。升级时取最近创建连接测试对应供应商的已保存文案，无可用记录则使用默认问候语。文案不影响指纹挑战。

“模型回复”直接显示在连接测试表单下方，随流式返回更新并支持复制；停止或失败保留已收到的正文。重开时显示当前或最近一次连接测试。回复只在应用运行期间保留，重启后的历史结果会提示正文未保留；模型和耗时等摘要仍可查看。

端点下拉选择已保存的主或辅助 base_url。测试、模型目录拉取和定时检测均固定访问选中地址，不自动切换端点，也不改变业务路由。模型目录按客户端、供应商和端点分别持久缓存，只有点击“重新拉取”才访问上游，包括首次拉取。打开弹窗、切换页面和重启均读取缓存；失败保留旧目录和选择。连接测试可选“默认模型”，优先使用所选端点缓存的默认值，无缓存时使用平台默认值。指纹和定时检测必须选择该端点缓存中的有效模型；目录不受路由白名单限制。连接测试和指纹检测各自记住每家供应商上次手动测试所选的模型，重新打开弹窗时沿用（连接测试上次选“默认模型”时仍为默认模型）；定时检测不改变这一记录。

测试失败展示 HTTP 状态及完整错误正文，包括 HTTP 200 中的错误和流式错误，支持复制；响应中的凭据脱敏，原始错误退出后释放。超过响应大小上限或读取中断时明确标注，历史仅保存错误摘要。

先通过对应客户端网关完成一次正常请求，应用才有可复用的 User-Agent。四客户端记录分别保存，成功的 HTTP 和 WebSocket 业务请求均可更新；探测、失败和测试请求不会覆盖。没有记录时测试会阻止并提示。测试直接访问所选供应商，不切换当前连接，也不计入普通业务用量。

Codex 的连接测试、模型目录拉取、指纹及定时检测还会从同一 User-Agent 提取配套的 originator，并只读当前选定 Codex 目录的 installation_id，校验 UUID 后发送 x-codex-installation-id。身份缺失、无法读取或格式无效时，显示具体原因并停止联网测试；不生成替代身份，读取已有模型缓存不受影响。客户端身份和安装标识的错误回显会脱敏。该组合覆盖上游默认的 Codex 客户端指纹检查；上游黑名单、版本区间和额外指纹要求仍然生效。明确的“仅允许 Codex 官方客户端”错误显示“上游限制客户端身份”，指纹任务立即停止，不自动重试、不判定降智或退队。

检测源在 ModelTrace 与 LM Detector 中二选一，按 Codex、Claude Code、Grok Build、DSH 各保存一套，同客户端的手动与定时检测共用。Codex 默认 ModelTrace，其他客户端默认 LM Detector；两个源分别记住组数，初始为 3 组与 1 组，均可选 1／3 组。改选立即自动保存，仅影响新任务；运行中及重试固定检测源、组数、资源、挑战和请求身份。手动并发不超过组数，定时始终串行。

3 组必须完成三组采样后汇总，不再因首组降智或 99% 匹配度提前结束。选择 1 组时有效预测可用于定时退队，LM Detector 单组标为“初步判断”，未校准置信度显示“—”。选择 3 组而不足三组有效时显示已有排名和失败原因，不自动退队；只重试确定可重试的失败组，成功组保留。

LM Detector 使用固定提交 `33fb43f26670be0ed7817ab13e5c4c4731ccb76a` 的离线 Rust SDK 子集（`lmfpd`）与配套公开数据包（内置基线 `33fb43f26670be0ed7817ab13e5c4c4731ccb76a`）构造挑战和完成闭集统计归因评分，所有评分在本机离线完成，不经过上游项目的在线代理或数据镜像；实际请求使用应用已有直连网络层及客户端身份。Codex 使用 Responses，Claude 使用 Messages，Grok 使用供应商协议，DSH 使用 Chat Completions 和实际模型映射。模型目录、评分参数与分词器库组成独立资源包；手动更新从同一个上游提交下载全部文件，校验文件哈希、配套关系和固定算法后原子替换，失败保留原资源。算法变化需要升级应用，已有任务仍使用原资源。

新源手动检测可附加分词器探测，每次打开默认关闭。数字采样结束后串行发送，最多 20 条探测与 2 次对照，每请求最长 90 秒；缺少用量、失败或取消即停止，不自动重试。提前收敛采用固定上游算法；结果独立显示，不改数字排名、不参与退队，失败保留指纹结果。“指纹库”页同时列出 ModelTrace 与 LM Detector 两个来源，各自显示来源（“内置”或“已更新”）、版本（七位提交号）、检查时间和更新结果，LM Detector 另显示更新时间；“一键更新”同时检查并更新两个来源，其中一个失败不影响另一个，失败原因显示在对应来源下方。

旧预约在升级时移除，不再执行。测试摘要与检测配置保留在本机，原始输出退出后释放。

四客户端的定时检测按“客户端＋供应商”分别设置启用状态、端点、模型和周期。新增客户端默认关闭且模型留空，选择缓存中的有效模型后才能开启。默认关闭，模式默认智能，下限 5 分钟；下限允许 5–30 整数分钟。最近一小时持久化网关业务调用每分钟按供应商分别统计，不计测试和重试次数：0 次暂停，1–2 次 30 分钟、3–9 次 25 分钟、10–29 次 20 分钟、30–59 次 15 分钟、60–119 次 10 分钟、120 次以上 5 分钟，实际周期取档位与该供应商下限中的较大值。统计失败暂缓派发并显示原因。固定周期默认为 15 分钟，允许 1–525600 整数分钟。

周期以最近一次已开始的自动检测完成时间为基准，首次启用无历史时使用启用时间；采样不顺延时间，修改一家不影响其他供应商。五分钟冷却从自动任务实际开始时计算；排队后取消不占冷却，手动测试不占自动冷却。同家任务互斥，派发前再次核对调用、配置、周期、队列与冷却。零调用撤销未派发的周期任务，已开始任务可完成。计时跨重启保存；无调用、休眠或退队后恢复时重新计时，不累计补跑。

自动检测仅在计划组数全部有效且汇总命中降智规则时标记并退出自动队列；选择 1 组时该单组即为汇总结果。手动变更优先，人工测试只报告结果；不执行降智复查，不自动清除标记或重新入队。清除标记和重新入队需分别手动操作，已绑定线程与手动使用沿用既有规则。

判定支持“严格模式 · 家族与版本层级”与“宽松模式 · 仅匹配指定降智模型”（默认目标 `gpt-5.6-luna`，仅允许当前指纹库非合并已知模型）两种本地策略。严格模式下使用实际发往上游的型号（DSH 使用映射后型号）：跨家族按本项目处置顺序 Claude ＞ GPT ＞ Grok ＞ DeepSeek，优先于家族内特例；未知家族或无法识别的别名不猜测。同家族：Claude 为 Opus ＞ Sonnet ＞ Haiku，同档旧版本降级，Fable 暂不定档；GPT 为 Astra ＞ Sol ＞ Luna，Sol 跨版本同级，Astra／Luna 同档旧版本降级，保留 gpt-5.6-luna 特例，其余未定档型号无法判定；Grok 同系列比较版本，fast、code 等不同系列不互比；DeepSeek 为 Pro ＞ Flash，同档比较主次版本，日期后缀不同不降级。合并类别仅在所有成员都降级时退队，其余显示无法确定。所有指纹结果均为参考库内的闭集统计分布排序，降级判定与自动退队仅作为本机网关路由调度策略，不构成对任何第三方服务商的模型真实性鉴定（详见 [README.md](../README.md) 与 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)）。

“未命中降智规则”与“无法判定”均不清除旧标记；退队失败保留标记和错误。`provider-tests.json` 仅识别 schema 3；其它版本或无法解析的文件会保留一份诊断副本并重置为默认设置。

## Codex 网络搜索

Codex 的网络搜索（`/v1/alpha/search`）与 Claude、Grok 一样由“接管网络搜索请求”管理：在供应商“编辑 API”弹窗的 API 分页勾选，可另外指定搜索模型和思考强度。开启后，搜索请求只在开启了该开关的供应商之间按列表顺序接力，不转入普通队列；没有任何供应商开启时，搜索按普通请求处理。完整规则见[客户端网关与调度](gateway.md)的“压缩、辅助与网络搜索请求接管”。

搜索请求没有单独的时限，与其他请求使用同样的超时、重试和等待预算；失败计入承接供应商的熔断与健康状态；承接顺序只看供应商列表，不优先线程原来的供应商。承接搜索的供应商照常参与普通请求、压缩和指纹检测，连接测试验证普通对话。

旧版本的“仅网络搜索”开关已不存在：载入旧设置时，这类供应商自动转为开启“接管网络搜索请求”，并从此开始接普通请求。
