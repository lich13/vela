# 用量、会话同步与定价

## 计量与请求表

供应商协议报告的缓存命中、缓存写入、5m／1h TTL 明细、推理 token 和输入口径会贯穿流式响应、存储、补缺和重启读取。推理 token 是输出子集，不重复加入总 token；解析冲突显示原因并保持未确定字段。请求速度与响应速度分开保存，响应明确为 `standard` 时不会沿用请求的 `fast` 价层。

请求列表固定分为身份信息、Token、费用、性能四个区域，同页共用列宽，各区域内容水平与垂直居中，数字在组内右对齐。默认行高 64px，启用额外性能字段后整页统一扩展；Token 固定两行，推理／命中率启用时增加第三列。紧凑和精确数字共用布局，图标、数字和费用不拆行，必要的横向滚动仅限请求表内部；窄窗口按整块区域重排。正文及表格数值 13px、辅助标签 12px、标题及概览主数值 18px，沿用系统字体与等宽数字。真实零显示 `0`，缺失显示“—”并在悬浮、键盘聚焦或详情说明原因。TPS 使用输出 Token 除以请求总耗时，不扣除首字时间；同步及流式请求共用口径。输出 Token 或总耗时缺失、无效，以及图片输出或本机会话无可靠耗时的记录显示“—”。长名称省略，完整内容通过悬浮和详情查看。

点击“统计中断”才会按当前筛选读取网关明细。每个逻辑请求只计一次，重试 attempt 不重复计数；“中断·用量不全”提示上游可能在断开后继续生成并计费，本地不估算。历史明细缺失显示证据不足，不按零计算。请求列表中被中断的网关请求在性能区另显示“已收”，即中断前从上游读取的数据量（按 1024 进位，如 `718.6 KB`）。

定价页的 models.dev 索引在首次缺少缓存、用户点击刷新和后台定时三种情况下联网：定时每 6 小时一次，出现未定价记录（含本机会话与 Antigravity 导入）后距上次尝试满 1 小时再试一次；刷新失败沿用旧索引，索引内容有变化时自动补价并刷新定价页。价格依次使用用户固定价格、远端明确价格、应用内置价卡和 models.dev 补充价格，保留显式映射及排除规则；价格核对显示当前参考来源、匹配依据、上下文阶梯和 25%／100% 偏差，不修改生效价格或历史快照。

“用量”显示本网关、本机 Codex／Claude Code 会话、Antigravity（app 与 CLI）请求，以及独立的 Grok 轮次汇总。网关按最终请求计数，Responses WebSocket 按生成轮次计数，重试详情及实际消费保留。HTTP 成功率同时核对真实状态码与业务完成状态；会话没有 HTTP 状态时显示“会话”，不伪造成功响应。该口径独立于熔断判定，HTTP 200 内的应用错误计为失败并记录异常。

顶部集中客户端、供应商和时间筛选；时间范围采用单层下拉菜单，预设范围（今日、最近 24 小时、7／14／30 天、全部）单击立即生效并关闭，点击“自定义”在同层展开起止时间与“跟随当前”。四项主指标为估算费用、已报告 Token、缓存命中率和平均首字，使用等宽等高区域，标签和数值组合居中；筛选、标签页（请求日志／供应商／曲线／模型／Claude Code／Antigravity／定价）及右侧操作统一控件高度与间距。连续指标区下方直接展示明细，不再显示请求数指标、展开指标或热力图，趋势只在“曲线”页签按供应商展示；可按生成、压缩、搜索筛选。请求、供应商和模型表均每页 20 条，支持跳页；刷新保留当前内容、页码和筛选。页面刷新默认 30 秒，可关闭；额度查询继续使用自己的间隔。

“数据来源”集中网关记录、会话同步开关、手动同步、各客户端采集状态与会话重建，并显示同步进度和导入、合并、关联待确认、失败数量。主页面不再常驻显示待核对提示和历史来源限制；数据归属可在来源面板或请求详情查看。重建采用事务，不删除网关记录；出现失败继续使用原数据。

Codex 优先读取单次 Token，缺失时使用累计差分；识别重复快照、多限额通道、累计重置和分叉重放。Claude 按消息 ID 合并主／子代理记录，保留中断时已报告的输入和缓存消耗，后到的完成项可以补全用量。跨来源优先按响应／消息 ID 合并，无 ID 时在时间窗口内按客户端、模型和各类 Token 做唯一匹配；多个候选标为“待核对”，不强行合并或混入合计。网关保留真实状态和耗时，精确响应／消息 ID 关联的会话可逐字段补齐缺失用量；已有非空值及真实零值不会被替换。无响应 ID 的签名匹配只用于去重，不补猜完全缺失的 Token。本网关筛选只显示网关原始采集值，全部记录可显示补齐结果，本机会话保留自身模型、时间和用量。详情区分上游未报告、提前结束、解析不完整和会话补齐。

Grok 原生 `turn_completed` 是一轮多次模型调用的汇总，使用“Grok 轮次汇总（独立）”来源查看，不与网关请求合计。输入拆分为非缓存输入、缓存读取和缓存写入，输出中的 reasoning 不重复相加；缺失字段保持未知。模型排行显示调用次数，多模型日志展示整轮 Token，模型筛选只汇总所选模型，详情仍保留完整轮次。无法可靠关联到网关时保持来源独立，轮次汇总不估算费用。

请求列表与请求详情对所有客户端标出模型的改写与不一致：请求列表的模型栏改为上下两行：第一行粗体显示请求模型；请求模型与上游请求模型不同时，下方以次要色小字显示“↳ 映射 上游请求模型”；发往上游的模型与收到的响应模型不同时，下方显示“↳ 返回 响应模型”，两种情况同时出现就各占一行。请求详情仍分“请求模型／上游请求模型／收到的响应模型”三项并带“映射”“响应不一致”标记。比较时忽略大小写、`/` 之前的前缀，以及结尾的日期后缀和 `-latest`。悬浮可见请求模型、上游请求模型和收到的响应模型。网络搜索记录和多次调用合并的 Grok 轮次汇总不作这一比较。

供应商／模型表显示名称、请求数、Token、费用、成功率和平均首字，上游尝试收进请求详情。请求数只计最终请求，实际消耗仍归属各次尝试。成功率只按结果已知的请求计算：只有一部分请求有结果时会写明笔数，例如“0.0%（3 笔已知）”表示 3 笔有结果的请求全部失败、其余结果未知（从会话导入的请求大多没有结果）；全部未知时显示“—”。输入缓存按客户端协议归一化，推理 Token 不重复加到输出。Claude Code 和 Antigravity 的全部已采集明细保留至导出；其他客户端明细默认 30 天，历史按用户时区整日汇总；无法逐条恢复的旧日汇总会保留并标明边界。已删除的旧网关数据无法恢复，现有会话可以重新导入；重建不重算已经计价的历史快照。

用量库采用 v12 存储结构，0.25.9 将数据库保护号升至 v13（沿用 v12 表），修复价格依据中小数经浮点转换后无法严格核对的问题。新数字编码保留 JSON Number 的原数字文本；旧整数和数字标签、压缩字典继续兼容。v0.43.0 将保护号升至 v14：防重账本的标识改存二进制、同步游标压缩保存，首次打开 v13 库时在一个事务内完成，内容不变。打开用量库时接受已完成就绪标记的 v13 与 v14 库，更高版本、更早版本或未完成迁移的旧库直接报错并保留原文件；v0.42.0 及更早的应用不能读取 v14 用量库。v0.44.0 为请求表和防重账本各新增一列访问 Key 标识，保护号仍为 v14：首次打开时补列并重建请求表的两个视图，不重写数据；v0.43.0 可以打开升级后的库，但不显示 Key 归属，由它归档的记录归入本机 Key。

请求与每次上游尝试的用量、价格快照、倍率和终态独立保存；相同计量和稳定元数据共享保存，诊断使用带完整性校验的二进制压缩。内部关联使用整数键，标准哈希与 UUID 无损保存为二进制，索引只用短检索值定位候选后仍比较完整标识。重复会话保留重新核对和撤销关联所需的证据，不依赖原会话文件继续存在。相同的网关原始值与补全值共用计量事实，实际差异单独保存。来源重建按批暂存，完整读取后才替换该来源；超过 10 万条的来源也可重建，失败或中断时原来源继续可用。

Claude Code 和 Antigravity 不参与按年龄归档。其他客户端最近 7 天保留可用细节。超过 7 天，仅对成功、用量与价格完整且没有异常证据的记录归档细粒度传输和路由诊断，并显示“细节已归档”；Token、费用、时间、真实终态、下游交付结果和关键路由结论保留。失败、取消、交付异常、未计价和待核对记录继续保留约 30 天细节。超过明细窗口后仍保留历史日汇总和防重账本。已计价请求的日汇总按天合并：同一天、同一来源视图下，客户端、来源、供应商、模型、速度与阶梯、价格规则与版本、倍率、操作类型和终态都相同的请求并成一笔，只保留各项合计；未计价的请求仍逐笔保留用量，之后补算价格的行为不变。合并后的日汇总不再保留逐笔 Token，不能按新价格重算（已计价的历史快照本来就不重算）。升级到 v0.43.0 后，旧的日汇总在后台分批并入，可中断、重启后继续，期间及完成后的概览、排行和倍率换算数字不变；全部并完后的下一次维护才回收空间，期间显示“用量存储正在回收空间”。整理和回收前检查临时空间；数据库忙、空间不足或维护失败时保留记录并延后重试。实库最终体积随记录数量和诊断内容变化，以升级后维护完成的测量为准。

平均首字衡量供应商响应耗时：从最终一次上游请求开始发送，到模型开始产出（内容块、输出项或工具调用开始，或首个非空文本、推理、工具参数增量，取最早者），包含该次连接和上游等待，不包含本地排队、RPM 等待及此前失败尝试。只使用有真实测量的网关流式生成请求，以首字总和除以有效样本数；本机会话、非流式和搜索不推算。无样本显示“—”，真实零毫秒保留，悬浮或键盘聚焦可查看精确值和样本数。旧日汇总没有首字信息时不会补造样本。

自动定价使用 Sub2API 配置的公开价格源 `Wei-Shaw/model-price-repo`，默认启动检查，此后每 10 分钟检查；SHA-256 完整校验通过后替换缓存。来源采用增量维护，检查成功不表示所有模型已更新至官方最新价格。价格检查独立于会话扫描与历史补算；JSON 与哈希暂时不同步时有限重试，失败继续使用缓存。内容未变时只更新内存检查时间，不重写价格缓存。定价搜索按模型 ID、名称和已知别名查询全部来源，按页加载，展示生效价格、来源和匹配依据。首次没有自定义定价文件时使用默认配置；已有文件损坏或被删除时保留有效价格。通常无需导入文件，文件操作收在高级菜单。手动价格和批量导入默认固定，支持恢复自动来源、筛选同步模型、排除项、独立定价文件和重新载入。

请求数和 Token 采用十进制 K／M／B，最多三位有效数字，悬浮、键盘聚焦及详情可查看精确值。请求按响应式多行排列：时间、供应商／客户端、模型与费用位于上层，Token 和性能位于下层。所有已启用字段直接可见，精确数字可换行；概览、筛选、统计和定价在默认与最小窗口均无需横向滚动。详情按基本信息、Token、费用、性能和尝试记录分组。常规概览、排名与明细固定使用请求去重口径；数据来源管理仍提供会话重建与同步控制，纯会话来源不借用网关首字测量。

定价页的“计费设置”集中计价模型、成本倍率和供应商精确映射。映射按客户端和稳定供应商 ID 隔离，默认关闭。规则匹配请求模型或收到的响应模型，只改变计价，不改变请求、白名单或路由；启用规则优先于通用计价模型选择，每次尝试保存规则版本和价格快照。上游隐藏内部模型且未提供可靠映射时，应用无法还原真实模型，不会自动套用更贵模型或统一倍率。

费用为 USD 估算值，支持缓存时长、服务等级、长上下文和已报告的媒体 Token 维度。信息不足时显示“未定价”，不猜测相似模型。内置 Token 价卡及明确别名依据 Sub2API `a3298b4` 随应用更新，Cyber 等独立变体分别计价，未知型号保持未定价；图片数量、视频秒数等计量不在此范围。Gemini 模型名末尾的思考档位和 `-tiered` 后缀只在去掉后的基础名有价格时才去掉，基础名仅 models.dev 有价时也按基础名计价（如 `gemini-4-neon-xhigh` 按 `gemini-4-neon`）；固定价格、远端价格和内置价卡的优先顺序不变，其他家族不做同样处理。DeepSeek 时段价格使用请求发生时间。已计价记录保留当时单价、来源、匹配依据和倍率；新价格只用于新请求及历史未定价记录。远端或 models.dev 价格变化后，以同一轮价格快照每批补价 128 条，批间释放写锁，覆盖明细和日汇总，中断可重试。

## 按 Key 统计

网关发放过访问 Key，或所选时间范围内有访问 Key 的用量时，筛选栏多出“Key”下拉（全部 Key／本机 Key／各访问 Key），标签页在“模型”之后多出“Key”；从未添加访问 Key 时页面没有变化。访问 Key 的规则见[网关](gateway.md)的“访问 Key”。

- 归属：请求记在它所用的那把访问 Key 下；没有使用访问 Key 的请求（包括升级前的全部历史和本机会话）归“本机 Key”。只记 Key 的标识，不保存 Key 本身。
- “Key”页签按 Key 列出请求数、Token、估算费用、成功率和平均首字，各 Key 之和等于总计。选了某把 Key 后，概览、请求日志、供应商和模型只统计它，Key 页签仍列出全部 Key。
- Key 的名称随网关的增删改更新，点“刷新用量”也会重读。已删除的 Key 保留用量，显示为 `Key` 加标识前 8 位；选“全部客户端”时访问 Key 的名称后带所属客户端。请求详情的“基本信息”对访问 Key 的请求多显示一项“访问 Key”。
- 定价页的倍率换算在所选客户端有访问 Key 时可按 Key 取数，用来按自定单价核算某把 Key 的费用；这里只列现存的 Key。用量页已按某把 Key 筛选时，换算器打开就落在这把 Key 所属的客户端；Key 名单还没读到时不会把全部 Key 的用量算在它名下，读取失败会提示“无法读取访问 Key，请重试”。换算器的客户端包含 Antigravity（仅本机，其他实例没有 agy 网关）。
- Claude Code 与 Antigravity 两个独立页签的统计不按 Key 区分，账单导出不按 Key 拆分。
- 超过明细窗口后日汇总按 Key 分开保存，筛选和排行对历史同样有效。同一响应 ID 的两笔网关记录只有属于同一把 Key 时才视为重复，其中一笔已经归档时也一样；本机会话与网关记录的去重规则不变。

## 供应商曲线

“曲线”页签（在“供应商”之后）按供应商展示错误率和首字随时间的变化，用来找出经常被限流或变慢的供应商。它跟随顶部的时间范围和客户端筛选。

- 选择供应商：左侧列出所选时间内有请求或有失败的供应商，被限流（429）最多的排在前面，其次按失败总数和请求数。每行是名称、错误率、429 次数、有结果的尝试数和错误率走势，各行走势共用一个刻度，可以直接比较。输入名称的一部分可以筛选，例如输入 `any` 只留下名称含 any 的供应商。点一行就查看这一家，顶部的“供应商”筛选随之切换，回到“请求日志”看到的就是它的请求；顶部选“全部供应商”时默认展示排在第一的那家。全部供应商的数据一次读回，切换不再查询。一次只画一家：两张图加四类失败叠上多家后读不清，要比较就看左侧各行。
- 错误率：每个时间格的错误率 = 失败 ÷（成功 + 失败），按对这家供应商的每次尝试计，重试和故障转移前的失败都算。失败分四类：429 限流、5xx、其他 4xx、中断（连不上、超时或响应中途断开，没有错误状态码）。图上的色带是各类失败所占的比例，亮线是合计，并标出 429 最多的一格；图下的细条是每格的请求量。
- 首字：每格首字时间的中位数（P50）和 P90，取实际测得的值，测量口径与“平均首字”相同。
- 汇总：区间错误率及其分子分母、429 次数和它占失败的比例、首字中位与 P90 及样本数；色条和图例是四类失败的构成。
- 读数：鼠标移到图上，或聚焦图后按左右方向键，逐格显示各类失败次数、成功数、错误率和首字；“表格”给出同一组数字。
- 时间格随范围自动取 5 分钟到 1 天，范围不超过 60 天时最多 60 格，更长按天。没有请求结束的格子把曲线断开，不画成 0；样本不足 5 个的格子淡显，纵轴上限按样本足够的格子取，避免一两次失败把整张图撑满。
- 数据从哪来：成功数和首字来自用量记录；失败来自运行日志，因为不限次重试的供应商被限流时不写用量记录。运行日志只保留最近 7 天，清空日志后从清空时算起。更早的时段标为“早于运行日志”，错误率是不可知而不是 0；只剩日汇总的时段没有首字分位，标为“只留有日汇总”。结果未知的请求既不算成功也不算失败。
- 运行日志不记录请求类型和访问 Key，这两项筛选在“曲线”页签停用；本机会话没有供应商，不在其中。概览的四项指标在这个页签隐藏。
- 选中服务器或另一台 Mac 时读取的是那个实例的数据；它的版本还没有这项功能时不显示“曲线”页签。

## 缺失用量与当前故障

Responses 流内有可靠响应标识的普通 `error` 等待同一响应的明确终态；随后正常完成可消除临时错误，没有后续终态则保留错误。未知原因的 `response.incomplete` 显示“上游未完成，原因未确认”。详情按需显示终态事件、状态、有限的未完成原因及上游响应关联摘要，原生 WebSocket 的握手摘要可由多轮共享。上游成功与下游交付异常分别保留，HTTP 200、用量和扣费均不单独证明成功；旧记录不补猜。

表格缺失字段显示“—”，详情与悬浮可查看未报告、提前结束、解析不完整、历史缺失或不适用。已知完整输入量及缓存读取即可计算 Codex 缓存命中率，不将未报告的缓存写入填为零。精确响应／消息 ID 可逐字段合并可靠会话元数据；本网关筛选保留实际采集值，全部来源可显示补齐值及来源。修复分批续行，历史已计价快照保留；没有原始依据的数据不推算。

日志保留数字和字符串上游错误码。连接超时、TLS 验证失败、断流等本地分类与上游返回码分别显示；最终失败和熔断继承实际触发原因。快捷面板显示当前故障及剩余等待时间，可打开关联日志。

请求详情中的结束原因区分协议完成、客户端断开、主动取消、网关停止和上游中断，并显示本次线程调度判定。HTTP 200 只代表实际响应状态；尚未收到完成事件便断开时，完成状态保持未知，不能仅凭已报告 Token 判定成功。已收到完成事件后再断开仍保留完成结果；历史缺少结束原因的记录不猜测补齐。

HTTP 响应或原生 WebSocket 握手建立后，客户端断开或写入失败会停止交付，并继续读取当前响应，直到上游 EOF 或固定 1.5 秒截止；读取失败、网关停止立即结束。收到终态或用量不再提前结束尾读，以保留稍后报告的输出量及缓存字段；内容、心跳和用量均不延长截止。响应头或握手前取消仍立即释放。该过程不重试请求，也不改变线程归属。截止后仍缺失的字段保持未知，可由后续精确关联的本机会话补全；自动同步继续遵循既有开关及 60 秒扫描间隔。

用量详情单独展示“最终路由结果”，与请求进入时的判定及边界快照区分。窗口登记、领取释放和归属保存等需要持久化的结果，等待保存回执后确认；保存失败保留错误。路由回执不重新计价、不增加第二笔用量，也不改写网络结束时间。旧记录缺少结果时不补猜，冷详情仍保留该结果。

普通维持供应商、压缩窗口消费和登记仅保留请求详情，异常日志的新记录、历史列表、数量和筛选统一隐藏这些信息。真实失败、熔断和实际接管继续保留，摘要优先显示失败原因，无需清空历史日志。

## Antigravity 与账单导出

用量页把 Antigravity app 与 Antigravity CLI（`agy`）合并为同一个客户端“Antigravity”：客户端筛选、请求表、详情、“Antigravity”独立页、数据来源和账单导出只显示这一个名称，经网关转发的 agy 请求也记在该客户端下。来源只作为次要信息出现在请求详情：“来源”区分网关与 Antigravity 会话，“传输”区分本地接口、历史文件与 CLI 会话文件。旧版本以 `agy` 为客户端保存的记录同样显示为 Antigravity；这只统一显示名，按 Antigravity 筛选、进入独立页或导出账单时不包含这些旧记录。

Antigravity app 通过本地只读接口及历史文件增量采集请求和重试。Antigravity 2.33.0 起，Vela 从 `~/.gemini/antigravity/daemon/` 下的 `hub_*.json` 与 `ls_*.json` 发现正在运行的实例，逐个探测后只使用有响应的，旧启动留下的文件不影响同步；更早版本沿用 App 窗口的调试端口。App 的会话列表没有列出、但本机会话库仍在的会话，按会话 ID 直接读取用量。可靠请求、响应标识用于去重；最终用量与相同响应的重试合并，保留有效模型、性能和错误码。模型显示名与思考强度取自每条记录自带的显示名，计价用的模型名由 App 返回的模型目录推导并保存为不带思考强度和 `-tiered` 后缀的基础名；该目录保存在用量数据库中，缺失、超过一天或遇到认不出的模型时重新读取。列表将模型显示名末尾已知思考强度拆为独立标签，详情和 CSV 分字段保存，并保留实际模型 ID；占位 ID 和显示名均不用于计价，价格源缺失时显示“未定价”，可在定价页手动设置。目前仍无价格的有 `gpt-oss-120b`、`gemini-pro-orchestrator` 系列，以及缺少输入或输出 Token 的记录。App 记在请求顶层的错误同样计为失败，其中“stream reading error: unexpected EOF”归为 `STREAM_INTERRUPTED`（显示“连接中断”）。成功请求已报告用量但缺少的输入、输出和缓存读取 Token 记为 0，缓存写入仍为未报告。推理 Token 是输出子集，不重复计费。

Antigravity CLI 的会话用量从本机会话文件只读导入，随现有会话同步执行，不需要 App 或 CLI 正在运行。每个会话读取 `~/.gemini/antigravity-cli/brain/<会话 ID>/.system_generated/logs/transcript_full.jsonl` 中已结束的模型步骤，取输入、缓存读取、输出 Token、模型名、步骤序号和时间；思考 Token、缓存写入、响应标识和步骤计时取自同一会话的 `~/.gemini/antigravity-cli/conversations/<会话 ID>.db`。计量口径与 App 采集相同，数值按原样保存：输入不含缓存读取，输出包含思考，思考是输出子集、不重复计费，未报告的缓存写入保持未报告。按文件偏移增量读取，重复同步不新增记录：末行未写完时留到下次，同一步骤被再次写入时以最后一行为准并原位更新，已随账单清理的明细不再导入；会话回到较早的步骤重新执行时（步骤序号倒退），重跑的步骤会再次计费，两次执行各记一条：每个步骤第一次执行沿用原记录，之后的重跑另存一条；会话库晚于会话文件写入时，待其变化后重读该会话补齐。会话文件只有步骤创建时间；首字用时和耗时取自会话库里该步骤元数据的三个时间戳（请求发出、首段内容出现、模型写完），三者齐全且先后顺序成立时，记录带有首字、耗时和 TPS。会话库里没有该步骤或时间戳不全时，若会话文件里紧随其后的是工具结果，耗时按“工具结果的创建时间 − 本步骤的创建时间”估算，耗时和 TPS 前加“≈”，悬浮提示“按下一步开始时间估算”；估算值只用于显示，不进入耗时合计、统计或账单。其后是用户输入、系统消息或文件结尾时不估算，耗时与 TPS 显示“—”；位于文件末尾的步骤等下一行写入后再补上估算。首字没有可用来源，缺失原因为“CLI 未记录”；步骤标记为出错时记为失败并保留错误码，其余记录的结果为“结果未确认”，不伪造 HTTP 状态。缺少步骤序号或时间的用量行不计入，并在“数据来源”显示为未同步。

CLI 记录的模型依次取该步骤自带的模型名、此前最近一次“Model Selection”设置变更中的显示名、会话库里该步骤的生成记录（内部模型名经已保存的 App 模型目录解析，否则用服务端模型名）；末尾的思考强度拆为独立字段，`-tiered` 后缀按上文规则回退到基础模型计价。都无法确定时模型留空并显示“未定价”，不猜测。agy 与 App 共用同一份登录，CLI 记录按请求时间归属到当时 App 的当前账号（沿用 App 记录使用的账号激活时间），计入该账号的 5h／7d 周期卡片、“账号分布”和账号筛选；早于账号库第一条激活记录的请求仍计入“本机会话”；登录保存在系统钥匙串（macOS）或凭据管理器（Windows）时没有登录开始的时间，第一条激活记录是 Vela 首次见到该登录的时刻，更早的请求归属到这第一个账号。入库时没有账号的记录在统计时按同一规则归属。账号卡片的某个周期在官方返回里被标为停用时显示“此账号未开放”，没有重置时间时显示“未返回重置时间”和剩余比例。升级到 v0.39.0 后的首次同步会重读全部 CLI 会话，为已导入的记录补上账号归属、估算耗时和重跑记录。

只有终端里的 agy 会经过 Vela 网关，这类请求既有网关记录，也会留下本机会话记录，两者只计一次并以网关记录为准。合并沿用现有跨来源规则：会话库中的响应标识与网关收到的 `responseId` 相同时精确合并；会话库读不到响应标识时，在时间窗口内按模型和各类 Token 做唯一匹配，多个候选标为“待核对”、不计入合计。两边的响应标识都有但不相同，或会话库读不到标识且模型名、Token 不完全一致时，无法判定为同一请求，两条记录都会计入合计。Antigravity app 不经过网关，不存在这类重复。

“账号用量”下拉按账号库顺序列出账号名称，每次只展示所选账号的卡片，总览、“账号分布”“模型家族分布”与已有筛选仍保持原统计范围。首次默认当前账号，普通刷新保留手动选择；App 当前账号变化时跟随切换，删除已选账号后回到当前账号。没有可用当前账号时显示“选择账号”，无账号时显示空状态。

所选账号展示 Gemini、Claude / GPT 两张卡，卡内显示当前 5h、当前 7d 的请求、Token、估算费用、起止时间和“速率”。速率是本周期估算费用除以周期开始到现在的小时数，显示为 `$x/h`（开始不足 1 分钟按 1 分钟算）；周期内的请求全部未定价时显示“未定价”。额度和周期边界由 Vela 用账号手头的访问令牌直接向 Antigravity 官方接口读取，不启动任何程序，本机实测一次约 0.6–0.7 秒（Vela 启动后的第一次还要查询账号所属项目，实测约 2 秒）。Vela 不为账号续期：访问令牌有时效（Google 的通常一小时），只有 Antigravity 自己（App 或 `agy`）会为当前登录的账号续期，它们在运行时令牌一般都有效。当前登录的账号在令牌到期、被官方拒绝，或官方接口没有给出结论（网络不通、超时或服务故障）时，依次改问 App 本机的 `RetrieveUserQuotaSummary`（核对 App 登录身份）和 `agy -p /usage --output-format json`（需要 `agy` 1.1.11 或更高版本，结果保留 60 秒）；官方返回限流时不改问，直接显示原因，并按其要求的时间暂停请求。非当前账号在令牌未到期时同样直接读取，到期后沿用上次读到的周期，切换到该账号后恢复读取。统计包含周期起点，不包含重置时刻，独立于历史日期筛选。打开 Antigravity 标签页时先显示历史和已保存的周期，随后才向当前实例请求一次额度，周期有变化时重读；额度读取慢或失败不再挡住历史。`agy` 对尚未动用的额度会把重置时间报成 1970 年，Vela 按没有重置时间处理，显示“未返回重置时间”和剩余比例，不再显示“未获取当前周期”。打开标签页、点“刷新用量”和打开托盘右键菜单时读取，各账号谁先有答案谁先更新，别处先读到新值时页面随即更新；自动同步仍只在 App 运行时向 App 本机接口采集当前账号的边界，不定时向官方接口查询。某个账号没有读到时沿用此前实际观测且未到期的周期，到期或从未读取时显示“未获取当前周期”，不推算下一周期。读取失败的原因只在所选账号是当前登录账号时显示：令牌到期后改用 `agy` 读取失败时是 `agy` 的原因（未找到 `agy`、版本过旧、需要重新登录、超时或被限流），官方接口没有应答或暂不可用时是它的原因；`agy` 要求重新登录或把 `/usage` 当成提问时，Vela 在本次运行期间不再为该账号运行它，重新登录后重启 Vela 或切换账号恢复。同步游标保留 App 返回的会话原名供账单使用，页面不再提供会话排行；标题变更不改变内部关联或历史费用。

修改价格、倍率或后台更新价格后，补算完成再刷新概览与当前数据；手动刷新模式也会接收该更新。来源操作直接使用命令返回的状态，并刷新统计与明细。

首字与生成耗时使用对应尝试报告的字段，总耗时仅来自可靠起止时间或完整的首字与生成耗时之和。输出 TPS 使用输出量／总耗时，详情另列生成耗时及生成 TPS；未知字段显示“—”。工具步骤结束不代表模型成功，已报告的失败、进行中与未知结果分别保留，不伪造 HTTP 状态。

已有记录会分批拆分已知思考强度，并用可靠首字及生成时间修正零耗时；来源已消失时保留现有数据。请求耗时优先使用该请求的有效起止时间，其次使用首字与生成耗时之和，无法确认时显示“—”。

“数据来源 → 补全 Antigravity 历史”手动重读该来源并原位补齐：先打开 Antigravity app 并保持运行，再进入“用量 → 数据来源”点击该按钮；App 未运行时提示“请启动 Antigravity app 后补全历史”。此前因连不上 App 而只从历史文件读到的记录，由本地接口返回的记录补齐。CLI 会话文件在补全时整份重读，不依赖 App 是否运行。可靠请求 ID、有效价格快照、统计和清理凭据保留，已清理明细不重复导入。普通同步隔离单个会话的读取失败并保留其位置供下次重试，其余会话继续同步。App 没有载入任何会话时会话目录为空，按“没有新内容”处理，不算失败。请求解析、历史文件读取、逐行解析、会话或额度读取失败时，“数据来源”显示“N 项未同步”及第一条失败原因，同步状态悬浮可见同一原因。明确标记为进行中的请求不算同步失败，游标保留到完成后补齐，重复同步不重复计量。账单需要完整来源，读取缺口仍会阻止导出与清理。同步复用增量偏移，本轮只索引所需步骤元数据，跳过内容未变化的写入。

“导出账单”可选择 Claude Code、Antigravity 或两者，起止时间使用本地时区、精确到秒，按请求结束时间包含完整尝试。CSV 不受列表分页限制，携带时区、请求及尝试标识、各维度 Token、价格、倍率、费用与计价依据，并附模型显示名、独立思考强度、服务来源、错误码、首字及生成耗时和两种 TPS。已有快照优先；缺少快照时冻结本次价格版本估算并标记，缓存、长上下文和服务档位按本次固定的 Sub2API 计费逻辑核对。

默认仅导出。勾选“删除历史记录用量”后，按钮变为“导出并清理”；成功保存后清理所选时间范围内已导出的明细与对应统计汇总，保留去重凭据。导出期间新增、变化或尚未结束的记录留待下次。取消保存、读取不完整、旧逐笔历史无法恢复或保存失败时不清理。曾经归并的历史按需从来源回读，不重复计入统计；来源已删除且从未采集的数据无法恢复。

Antigravity app 首字保留接口报告值；首字耗时和生成耗时齐全时，总耗时优先取两者之和，输出 TPS 为输出 Token／总耗时；Antigravity 的记录（App 与 CLI）在输出不足 200 Token 或耗时不足 1 秒时不计算，显示“—”并在悬浮说明原因。请求详情的“生成 TPS”为（输出 − 思考）÷ 生成耗时：Antigravity 的输出包含思考，而生成耗时只从首段内容出现算起，不扣除思考会得到远高于实际的速度；生成耗时不足 100ms、不足 1 秒且首字用时超过它的 4 倍，或结果超过 10,000 tok/s 时不显示。账单 CSV 保留原始的生成耗时、输出与思考 Token，其中的生成速度列仍按“输出 ÷ 生成耗时”（生成耗时大于 50ms）计算。上游报告的首字接近结束时仍如实显示，不使用推算首字；历史补正只调整可证明错误的性能值，保留请求身份、Token、价格快照及清理凭据。

## Claude Code 独立用量

“用量 → Claude Code”汇总有效网关记录与本机会话，沿用请求去重、重试消耗和历史费用快照。显示请求数、会话数、Token 构成、缓存命中与节省、供应商分布、完整模型标识，可跳转请求详情。采集上游与本机会话上报的 `thinking_tokens` 并跟踪思考内容块；升级时通过递增 `source_generation_claude` 无损重扫磁盘现存会话文件回填思考占比并补齐关联网关记录，源文件已被清理的更早历史记录完整保留且未报告的思考等字段显示“—”。Claude Code 与 Antigravity 独立页固定对应客户端，切换平台清空不适用的供应商、会话；日期和请求类型筛选继续生效。供应商筛选按最终供应商选中整条请求并统计全部尝试，任一尝试未定价时该请求只计入一次未定价。

两个独立页的缓存节省按每次请求保存的价格依据、服务档位与倍率比较，不随当前倍率或价格目录变化；缺少可用快照显示“—”，原费用与 Token 不变。

官方额度单独读取当前配置目录的 Claude 登录凭据：macOS 使用 Claude Code 的钥匙串规则及文件回退，其他平台读取 `.credentials.json`。Vela 不写入或续期凭据，不猜测历史记录的账号。额度显示官方返回的 5h／7d 和适用专属周期已用比例与重置时间，不换算为 Token 或费用。结果只在内存缓存五分钟，页面可见时沿用用量刷新；手动刷新重新查询，429 遵守重试时间。失败就地显示错误，本机统计继续可用。

“用量 → 定价 → 倍率换算”为独立试算工具，按所选周期内的网关用量和填写的单价计算消耗金额。先选客户端、供应商（默认“全部供应商”）和模型（留空为全部模型；从下拉菜单选择当前客户端已使用的去重模型会自动带出有效单价，未定价模型仍可选中用于筛选），再填输入、输出、缓存读取、5 分钟缓存创建、1 小时缓存创建五项单价（美元／百万 Token）。周期为开始与结束两个本地时间，精确到秒，默认沿用用量页当前的时间范围，没有时为今天 0 点到现在；开始晚于结束时就地提示。点“计算”读取该周期内符合条件的网关尝试用量（未标时长的缓存创建余量归入 5 分钟缓存），按定点十进制计算并列出每项的 Token、单价、费用与总额；没有符合条件的用量时提示“所选周期没有符合条件的网关用量”。归属按每次真实上游尝试，失败后换商的消耗仍计入原供应商。试算不修改计费设置、历史记录或价格快照。
